# 여운 이용약관·개인정보처리방침

홈페이지의 `/yeoun/terms/`·`/yeoun/privacy/` 에 싣는 문서의 **시행본**이다.

- 작성·개정의 원본은 앱 리포의 `legal/terms-of-service.ko.md`·`legal/privacy-policy.ko.md` 다. 여기서는 문구를 고치지 않는다. 고칠 일이 생기면 앱 리포에서 고치고 새 판으로 들여온다.
- 영어 초안(`legal/*.en.md`)은 싣지 않는다.
- 파일 이름은 시행일이다(`terms/2026-11-20.md`). 한 번 시행한 판의 파일은 바꾸지 않는다. 옛 판은 `/yeoun/terms/2026-11-10/` 처럼 날짜 주소로 계속 보인다.
- 최초 판(2026년 8월 10일 시행)은 확인된 원문이 없어 싣지 않았다. 각 문서의 개정 이력(부칙, 방침의 변경)에 시행일만 남아 있다.
- 사이트는 개발자 이름을 싣지 않는다. 예외는 하나다. 개인정보처리방침의 '개인정보 보호책임자' 항목(`성명: …`)은 방침에 꼭 적어야 하는 사항이라 원문대로 싣는다. `src/pages/Legal.test.tsx` 는 이름이 이 항목에만 한 번 나오는지 확인한다. 이용약관, 사이트 문구, 제목, 다른 페이지에 나오면 테스트가 잡는다. 이름을 빼려면 앱 리포 원문을 고친 뒤 새 판(새 시행일)으로 들여온다. 이미 시행한 판은 그대로 둔다.

| 파일                                  | 내용                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| `terms/*.md`, `privacy/*.md`          | 시행본 원문. 앱 리포 파일을 바이트 그대로 복사                                |
| `legal.json`                          | 문서 이름·주소·판 목록(최신 = 현행이 맨 앞)과 페이지 문구                     |
| `documents.json`                      | 빌드 때 만든 HTML(`scripts/legal-docs.js`). 직접 고치지 않는다               |

## 새 판을 싣는 법

**새 판은 시행일 당일에 싣는다.** 판 목록(`legal.json` 의 `versions`)의 맨 앞은 언제나 '현행'으로 표시되고 문서의 기본 주소에 걸린다. 시행일 전에 실으면 아직 시행하지 않은 판이 현행으로 보이고, 지금 시행 중인 판은 옛 판이 된다. 공고 기간에는 공고만 하고, 이 폴더에는 아무것도 넣지 않는다.

예: 이용약관 2027년 1월 1일 시행본(2027년 1월 1일에 싣는다)

1. 앱 리포에서 시행본이 확정된 커밋의 파일을 그대로 복사한다.

   ```sh
   git -C ../yeoun cat-file blob <커밋>:legal/terms-of-service.ko.md > src/content/legal/terms/2027-01-01.md
   ```

2. `legal.json` 의 `documents.terms.versions` **맨 앞**에 `"2027-01-01"` 을 넣는다. 맨 앞이 현행이고, 나머지는 옛 판이 된다.
3. `yarn legal` 로 `documents.json` 을 다시 만든다(`yarn start`·`yarn build` 도 먼저 만든다).
4. `src/data/pageMeta.json`
   - 직전 현행 판의 항목을 더한다: `"yeounTerms-2026-11-20"`, `path` `/yeoun/terms/2026-11-20/`, `file` `yeoun/terms/2026-11-20/index.html`, 제목·설명에 시행일, `"noindex": true`.
   - 현행 항목(`yeounTerms`)의 설명에 적힌 시행일을 새 날짜로 바꾼다.
5. `CI=true yarn test --watchAll=false` 로 확인한다. 목록에 없는 파일, 파일 이름과 본문 `시행일:` 줄이 다른 날짜, 빠진 `pageMeta.json` 항목, 다시 만들지 않은 `documents.json` 은 테스트가 잡는다.

## 쓸 수 있는 마크다운

`scripts/markdown.js` 는 지금 문서가 쓰는 문법만 그린다: `#`~`###` 제목, 문단, `-`·`1.` 목록(한 단계 들여쓰기까지), 표, `**굵게**`, 이메일 주소(메일 링크). 인용(`>`), 링크(`[..](..)`), 코드, 기울임, 주소 링크처럼 그 밖의 문법이 들어오면 빌드와 테스트가 멈춘다. 새 문법이 필요하면 렌더러와 그 테스트를 먼저 늘린다.
